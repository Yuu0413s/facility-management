# Excel取り込み・Tag 追加 設計メモ

## 1. 目的

Excel からの一括取り込みで、バックアップ（全件出力）からの復元と、既存資料からの移行をできるようにする。あわせて、PC を識別する「Tag」を管理できるようにする。

## 2. ユーザー

- 既存と同じ社内の2名（権限の区別なし）
- 取り込みも2名とも使える

## 3. 課題

- 機能追加などでデータが消えたときに、全件出力した Excel から元に戻せるようにしたい
- これまで別の Excel で管理していた情報を、手入力し直さずに移したい（列の並びなどの形式合わせは手動で行う）
- 空欄が多い Excel でも取り込めること

## 4. 機能

### MVPに含める

| 機能 | 仕様 |
|---|---|
| Tag の入力 | 任意の自由入力。前後の空白を除く。重複禁止（大文字・小文字は区別しない）。PC名の次に配置 |
| Tag の検索 | 既存の検索窓で「施設名または Tag」の部分一致 |
| Tag の並べ替え | 列見出しクリックで昇順／降順。空欄は最後。同じ値どうしは施設名→PC名の昇順 |
| Excel 取り込み | 最初のシートの1行目の見出し名で列を判断（並び順自由・知らない列は無視・無い列は空欄）。全項目空欄の行は読み飛ばす。1回1,000行まで |
| 取り込みの反映 | 「施設名＋PC名」が一致すれば上書き、なければ追加（アップサート）。**上書きは値の入っている項目だけ**（空欄のセル・ファイルに無い列は既存の値を残す。取り込みで値を消すことはできず、消すときは編集画面を使う）。Excel に無い既存行は残す。施設名かPC名が空欄の行は常に追加 |
| 取り込みのエラー | 正しい行だけ取り込み、エラー行は行番号と理由を一覧表示 |
| 取り込みの確認 | 実行前に「同じ施設名＋PC名のデータは、値の入っている項目だけ上書きされます」の確認ダイアログ |
| 日付セル | `yyyy/mm/dd`、`yyyymmdd`、Excel の日付セル（UTC の年月日として読む）を受け付ける |
| Key | ハイフンあり・なし両方を受け付ける（既存の正規化と同じ） |
| Excel 出力 | 全件出力の PC名の次に Tag。アカウント情報出力は変更なし |

### MVPに含めない

- 取り込み前の件数プレビュー（追加／上書き／エラーの事前表示）
- 全件入れ替え
- アカウント情報出力の形式からの取り込み

## 5. 画面構成

```
一覧ページ
  ├── [Excel出力] → 全件出力 / アカウント情報出力
  └── [Excel取り込み] → ファイル選択 → 確認ダイアログ → 実行
                         → 結果表示（追加・上書き・読み飛ばし件数、エラー行一覧）→ 一覧を再取得
登録・編集ページ
  └── PC名の次に Tag の入力欄
```

## 6. データ構造

```sql
-- db/migrations/003_add_tag.sql
ALTER TABLE facility_pcs ADD COLUMN tag TEXT;
CREATE UNIQUE INDEX facility_pcs_tag_lower_key ON facility_pcs (lower(tag));
```

- NULL どうしは重複とみなされないので、Tag 空欄の行はいくつでも登録できる
- 重複エラー（23505）は違反した制約名で出し分ける
  - `facility_pcs_facility_name_pc_name_key` → 「同じ施設に同じPC名がすでに登録されています」
  - `facility_pcs_tag_lower_key` → 「同じTagがすでに登録されています」

## 7. API設計

| メソッド | URL | 用途 | 成功 | 失敗 |
|---|---|---|---|---|
| POST | `/api/facility-pcs/import` | 一括取り込み | 200 | 400（行数超過・形式不正） |

- Excel の読み取りはブラウザ側（ExcelJS、動的 import）。サーバーには行データを JSON で送る
- リクエスト: `{ rows: [{ rowNumber, facilityName, pcName, tag, ... }] }`（最大1,000行）
- レスポンス: `{ created, updated, errors: [{ rowNumber, messages }] }`
- サーバー側の処理
  1. 各行を既存の入力スキーマで検証（エラー行は errors へ）
  2. ファイル内の重複（同じ施設名＋PC名、同じ Tag）は後から出てきた行をエラーにする
  3. DB 上の Tag 重複（別の施設名＋PC名の行が同じ Tag を持つ）を1本の SQL で事前確認し、該当行をエラーにする
  4. 残りの行を1本の SQL（`INSERT … SELECT FROM json_to_recordset … ON CONFLICT (facility_name, pc_name) DO UPDATE SET 列 = COALESCE(EXCLUDED.列, 既存の列)`）でアップサート
- 一覧の `q` は施設名または Tag の部分一致。`sort` に `tag` を追加

## 9. 実装手順

1. Tag の追加（DB → スキーマ → リポジトリ → API → 画面 → Excel 出力）
2. 取り込みのサーバー側（行ごとの検証、ファイル内・DB 上の重複確認、一括アップサート）
3. 取り込みの画面側（Excel の読み取り → 確認 → 送信 → 結果表示）

## 10. リスク

| # | リスク | 対策 |
|---|---|---|
| 1 | Cloudflare の1リクエストあたりの外部通信回数の上限（無料プランの値は不確か） | 事前確認とアップサートをそれぞれ1本の SQL にまとめる |
| 2 | ファイル内で同じ施設名＋PC名が複数行（1本の SQL で同じ行を2回更新できない） | 後から出てきた行をエラーにする |
| 3 | Tag がファイル内・DB 上の別の行と重複 | 事前に確認してその行をエラーにする |
| 4 | Excel の日付セルの時差 | UTC の年月日として読む |
| 5 | 列追加のため、公開前から開いていたタブで保存すると Tag が空欄で上書きされる | 公開後に全員で再読み込み（README の手順） |
| 6 | 1,000行を超えるファイル | 取り込まずに分割を案内する |
| 8 | 列の少ない・空欄の多い Excel で既存の値が空欄に上書きされる | 上書きは値の入っている項目だけ（COALESCE） |
| 9 | 2行の Tag を1回の取り込みで入れ替えられない（どちらも Tag 重複エラーになる） | 仕様として許容。編集画面で直す |
| 7 | 事前確認とアップサートの間に別の利用者が同じ Tag を登録する | 利用者2名のため許容。起きた場合は一括アップサートが 409 相当で失敗し、何も取り込まれない（再実行で解消） |
